## Invariants → Enforcement Mapping
| # | Invariant | Type | Enforcement Point | RAP Mechanism |
|---|-----------|------|-------------------|----------------|
| 1 | Discount ≤ 30% | Validation | validateDiscount | Validation method in BDEF (on save); determination CalculateDiscount caps value before save |
| 2 | Offer expires after 72 hours | Determination | determineExpiry | Determination on modify { create; } sets ValidTo = CreatedAt + 72h; Application Job sweep sets Status=Expired |
| 3 | Only one active offer per contract at any time | Validation + Lock | validateSingleActiveOffer | Validation on save (query active offers for ContractUUID); lock scope ContractUUID prevents concurrent create |
| 4 | Approval required above configurable threshold | Validation + Action | validateApprovalStatus + requestApproval | Validation on save checks ApprovalStatus when Discount > ApprovalThresholdAtCreation; action requestApproval → SAP workflow |

All four invariants map to concrete RAP mechanisms. No design problem flagged.
